Workflow작동 순서

train → run → dashboard
01

과거 학습·평가

history.json 매니페스트와 과거 스냅샷으로 학습합니다. 기준선, 로지스틱 회귀, HistGradientBoosting 등 후보 5개를 검증 기간의 Precision@K로 비교하고, 선택한 모델을 미래 기간으로 다시 평가합니다. 평가 후 재학습하지 않습니다.

02

현재 재직자 예측

고정 모델로 현재 파일의 점수를 계산합니다. 모델의 회사·퇴사 유형·기간이 질문과 맞는지 검사하고, 상위 K명·다음 K명·나머지로 구간을 나눕니다. 모델이 없으면 명시적으로 요청했을 때만 진단 모드로 실행합니다.

03

대시보드

직원 목록을 먼저 보여 주고, 조직·검색·위험 구간·유지 우선순위·상태 필터를 모든 패널에 똑같이 적용합니다. 담당자·확인 상태·다음 확인일은 브라우저에 저장하고 JSON으로 내보내거나 가져옵니다.

Dashboard대시보드 화면

single html · no cdn
  • 01직원 목록실제 값·단위·기간·비교 기준을 근거로 붙인 퇴사위험 순위표
  • 02조직별 지표 히트맵지표별 전체 명부 백분위. 퇴사위험 기여도가 아님을 화면에 명시
  • 03위험 구간 분포상위 K · 다음 K · 나머지 구간과 유지 우선순위의 교차표
  • 04근무·설문 추이월별 연장근로 추이와 최근 설문 차트. 원본이 없으면 이유를 표시
  • 05확인 기록담당자 · 확인 상태 · 다음 확인일 · 유지 우선순위. 회사별 브라우저 저장, JSON 내보내기·가져오기
  • 06공유용 파일이름·사번을 가명으로 바꾼 별도 HTML

Principles지키는 원칙

from the README
  • R1점수는 순위용보정된 퇴사 확률이 아닙니다. 0.7을 "퇴사 확률 70%"라고 말하지 않습니다.
  • R2재학습 금지현재 파일의 라벨로 학습과 예측을 동시에 하지 않습니다. 예측 실패를 진단 성공으로 바꾸지 않습니다.
  • R3민감 속성 배제민감 속성·병가·설문 미응답은 개인 예측 입력으로 쓰지 않습니다.
  • R4유지 우선순위 분리유지 우선순위는 HR이 지정하는 업무 판단이며 퇴사위험 점수와 합치지 않습니다.
  • R5합성 데이터 구분동봉 샘플은 처리 경로 검증용입니다. 실제 회사 성능은 실제 과거 데이터로 검증해야 합니다.

Triggers실행 문구

attach an xlsx
  • 퇴사 위험 분석해줘
  • 누가 그만둘 것 같은지 알려줘

  • 이탈 가능성 예측해줘

HR 엑셀을 첨부하며 말하면 예측 스킬이, 결과 엑셀이 있으면 대시보드 스킬이 실행됩니다.

Install설치

plugin or skills

Claude Code · 플러그인

플러그인 ZIP을 풀어 둔 뒤 Claude Code에서 마켓플레이스로 등록하고 설치합니다.

/plugin marketplace add <풀어 둔 hr-attrition 폴더>
/plugin install hr-attrition@tpc-hr

엔진은 Python 3.11 이상과 pandas · numpy · openpyxl · scipy · scikit-learn이 필요합니다. 폴더에서 pip install -e . 로 설치합니다.

Claude.ai · 스킬 2개

claude.ai에서는 스킬 ZIP을 각각 업로드합니다. 설정 → 기능(Capabilities) → Skills. 두 ZIP 모두 공용 엔진을 동봉하고 있어 단독으로 동작합니다.
